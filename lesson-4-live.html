本讲主题：盲目搜索（无信息搜索）

  • 上一讲我们建立了搜索框架：边界（frontier）、路径、问题解、解的代价；搜索树。
  • 搜索算法主要性能评价指标：完备性、代价最优性、时空复杂度。
    • 完备性（completeness）：当问题存在解的时候，这个算法是否能保证找到解；当不存在解时，是否能保证报告失败？
    • 代价最优性（cost optimality）：搜索将总是找到成本最低的解决方案吗？（当动作有成本/路径耗散（path cost）时）
    • 时间复杂度（time complexity）：找到解需要花费多少时间？
    • 空间复杂度（space complexity）：在执行搜索的过程中需要多少内存？
  • 有信息搜索（informed search）：它利用启发式函数（heuristic function, h(n)），去估计某个非目标状态离目标状态的"希望程度"/"代价"，从而指导搜索顺序。
  • 无信息搜索（uninformed search）/盲目搜索（blind search）：它对问题的状态空间只有基本的定义（初始状态、目标测试、后继函数、路径代价），没有任何关于目标位置的额外知识。因此它不能判断一个非目标状态是否更接近目标，只能依靠系统性遍历或规则来扩展节点。

广度优先搜索（breadth-first search, BFS）——图搜索算法的一个实例

基本思想

  • 从初始状态开始，一层一层地向外扩展，即先扩展距离初始状态最近的节点，再扩展更远的节点。
  • 使用队列（FIFO / First In, First Out）作为存储结构，存储等待探索的状态。
    • FIFO 举例：先入库的货物先出库，避免存货过期。

步骤

  1. 将初始状态放入队列。
  2. 重复以下操作，直到队列为空或找到目标：
    • 从队列头部取出一个节点。
    • 如果该节点是目标，结束搜索。
    • 否则，扩展该节点的所有后继状态，并将它们加入队列尾部。

广度优先搜索（breadth-first search, BFS）

  • 先把初始状态放到边界上。
  • 把所有能从初始状态恰好一步能到达的状态都放到边界上；把路径添加到边界。
  • 把所有能从初始状态恰好二步能到达的状态都放到边界上；把路径添加到边界。
  • 把所有能从初始状态恰好三步能到达的状态都放到边界上；把路径添加到边界。
  • ……

广度优先搜索的性质

Big-O 表示法

  • 树的表达可以用来评估时空复杂度。
  • 什么是时间复杂度？衡量算法运行时需要执行多少步操作（扩展多少个结点）。
  • 在 BFS 中，最主要的操作就是生成和检查节点。
  • 所以 BFS 的时间复杂度 ≈ 需要扩展的节点总数。

BFS 的搜索过程可以抽象为一棵状态空间树：

  • 根节点：起点 START（深度 0，路径长度 1）。
  • 每个节点最多生成 b 个子节点（这里 b 称为最大分支因子）。
  • 如果解的深度为 d，那么 BFS 要把深度从 0 到 d 的所有节点都扩展出来（直到找到解），所以 d = 路径长度 − 1。

在一棵 b 分支的树里，每个结点的最大后续状态数目（即最大分支因子），假设 d 是解的深度：

  • 深度 0：有 1 个节点（根）。
  • 深度 1：最多有 b 个节点。
  • 深度 2：最多有 b2 个节点。
  • 深度 3：最多有 b3 个节点。
  • ……
  • 深度 d：最多有 bd 个节点。

因此，总节点数是一个等比数列：

1 + b + b2 + b3 + … + bd−1 + bd = (bd+1 − 1)/(b − 1)

当 b 很大、d 也很大时，总节点数近似为 bd+1（呈指数级增长）。

时间复杂度：N ≈ O(bd+1) / 近似写法 O(bd)

广度优先搜索的性质

完备性：如果解存在，BFS 一定能找到。

代价最优性：在所有代价相等的情况下，BFS 保证找到最短解。

  • 先检查深度 0（起点），再检查深度 1（一步之遥的状态），再是深度 2……直到深度 d。
  • 一旦 BFS 找到目标节点，就保证这个目标是到达目标的最短路径（以步数为代价）。
  • 如果每一步代价不同（例如走一步花 1 元，走另一条捷径可能花 5 元），BFS 找到的只是步数最少的路径，而不一定是代价最小的路径。

时间复杂度：O(bd)，其中 b 是分支因子，d 是最浅目标深度。

空间复杂度：同样为 O(bd)，因为需要存储所有层的节点。

BFS 的现实问题：空间复杂性

举例来说：每个结点平均分支数 10，一个平均每秒可以扩展十万结点的搜索树，如果每个结点要求 100 字节的话：

深度优先搜索（depth-first search, DFS）

基本思想

  • 从初始状态开始，尽可能沿着一条路径向下走到底（到达目标或死路），再回溯到上一个分支点继续探索。
  • 使用栈（LIFO / Last In, First Out）作为存储结构，或者递归实现（最后放进去的元素，最先被取出来）。

步骤

  1. 将初始状态放入栈。
  2. 重复以下操作，直到栈为空或找到目标：
    • 从栈顶取出一个节点。
    • 如果该节点是目标，结束搜索。
    • 否则，将它的后继状态依次压入栈顶。

示例：网格世界

  • 假设状态是网格中的一个格子，你能东北西南移动，那么 DFS 算法怎么操作呢？假设你每次都先往东，然后再北、西、南。
  • 扩展顺序：E, N, W, S
  • BFS 算法又会怎么做呢？

性质

算法是完备的吗？

  • 如果问题的状态空间是有限的（节点数有限），那么 DFS 最终一定会把所有节点都遍历一遍。即使它可能绕来绕去，但因为状态总数有限，它总会"回到头"，最终能找到目标。
  • 如果状态空间是无限深的树：DFS 会盯住某一条路径一直往下走，可能永远走不出来。这样，即使解在另一条浅层路径上，DFS 也可能永远找不到。
  • 所以在无限深度的状态空间中，DFS 不保证完备。

代价最优性？

  • 不保证最优解，因为 DFS 可能先找到一条较深但代价高的路径。

时间复杂度？

  • O(bm)，m 是最长路径的长度。（类似 BFS 的计算方法，最坏情况下要访问所有节点。）

DFS v.s. BFS

  • 当 m ≫ d 时，DFS 可能比 BFS 慢得多，因为它可能探索到无关的深层节点。
  • 如果解分布得比较密集，DFS 有机会比 BFS 更快找到一个解，因为它不必像 BFS 那样逐层全面展开。

空间复杂度？

  • O(bm)，线性的！ —— DFS 的数据结构通常是一个栈（DFS 的显著优势）。
  • 一次只探索一条路径。在最坏情况下，它需要记录：
    • 路径上的所有结点：深度最多 m，所以至少要存储 O(m)。
    • 每一层的兄弟结点（尚未展开的后继）：在深度为 0 的根节点，可能有 b−1 个兄弟未展开；在深度为 1 的节点，同样可能有 b−1 个兄弟未展开；以此类推，深度为 m 时仍可能有兄弟节点等待回溯。
    • 所以在最坏情况下，除了当前路径长度 m，还要额外存储大约 (b−1) × m 个兄弟节点 → O(bm)。
图中红框标出的即各层的兄弟节点（回溯点）。

DFS 的问题：

  • 在无限状态空间里，DFS 可能沿着一条路径无限深入，永远回头→找不到解。
  • 在有限但很深的空间里，DFS 可能先找到一个很长的解，而忽视更短的解。

解决办法：

  • 设定一个最大搜索深度 ℓ。
  • 超过深度 ℓ 的路径就不再展开。
  • 这样可以避免"路径太长"或"无限下探"的问题。

➡ 使用深度受限搜索！

深度受限搜索（DLS）的规则

  • 从根节点开始（深度 = 0）。
  • 沿着路径往下扩展，但只允许走到深度 ≤ ℓ。
  • 到达深度 ℓ 时，不再继续往下展开。
  • 因此，所有路径都被"截断"在 ℓ 层以内。

优点

  • 避免 DFS 在无限路径里走不出来。
  • 节省内存空间。

缺点

  • 只能找到深度 ≤ ℓ 的解。
  • 如果真正的解在更深处（> ℓ），DLS 就会失败。

伪代码

DLS (Frontier, Successors, Goal?)   /* Call with Frontier = {<START>} */
WHILE (Frontier not EMPTY) {
    n = select first node from Frontier
    Curr = terminal state of n
    If (Goal?(Curr)) return n
    If Depth(n) < ℓ          // Don't add successors if Depth(n) = ℓ!!
        Frontier = (Frontier – {n}) U Successors(Curr)
    Else
        Frontier = Frontier – {n}; CutOffOccured = TRUE.
}
return FAIL

迭代加深搜索（IDS，Iterative Deepening Search）

原理：通过扩展深度受限搜索来解决 DFS 和 BFS 的问题

  • 从深度限制 ℓ = 0 开始，我们迭代地增加深度限制，对每个深度限制执行深度受限搜索。
  • 如果找到解决方案，或者如果深度受限搜索失败且没有截断任何结点，则停止。
  • 如果没有结点被截断，搜索将检查状态空间中的所有路径，并且发现没有解决方案 → 不存在解决方案。

完备性？

  • 是的——如果深度限制为 ℓ 的解存在的话（即解存在且深度已知上限时，IDS 一定找到最浅解）。

时间复杂度？

  • 深度 0 的节点访问了 d+1 次。
  • 深度 1 的节点访问了 d 次。
  • 深度 2 的节点访问了 d−1 次。
  • ……
  • 深度 d 的节点访问 1 次。
  • (d+1)b0 + db1 + (d−1)b2 + … + bd = O(bd)
  • 例如：b=4, d=10：(11)·40 + 10·41 + 9·42 + … + 410 = 1,864,131
  • 410 = 1,048,576，大多数结点位于底层。

空间复杂度？

  • IDS 的存储方式和 DFS 完全相同，空间复杂度 O(bd)。

IDS —— 结合 BFS（完备、找到最浅解）和 DFS（省空间）优点的折中方案

BFS 比 IDS 可以探索更多的状态！

  • 时间复杂度 IDS：(d+1)b0 + db1 + (d−1)b2 + … + bd = O(bd)
  • 时间复杂度 BFS：1 + b + b2 + b3 + … + bd + b(bd−1) = O(bd+1)
  • 当 BFS 展开第 d 层的节点时，会生成第 d+1 层的所有子节点（即使这些子节点不会被继续展开，因为在第 d 层已经找到了解）。
  • 设 b=4, d=10：
    • IDS：(11)·40 + 10·41 + 9·42 + … + 410 = 1,864,131（产生的状态数）
    • BFS：1 + 4 + 42 + … + 410 + 4(410−1) = 5,592,401（产生的状态数）

一致代价搜索（UCS，uniform-cost search）

当存在路径代价时……

  • UCS 在边界中要把路径代价进行升序的排序。
  • 始终扩展代价最低的节点。
  • 如果每个动作都具有相同代价，那么 UCS 等价于 BFS。

关键观察

  • 在已达表（reached）的帮助下，我们了解到通过 d 到达 e 的路径比以前找到的路径代价更小！因此调整了状态 e 的代价（9 → 5）。
  • 问：为什么更新 q 而不是 p？它们都是 h 的后继状态。
    • 答：p 早已以更小代价 (p,1) 被从优先队列中取出并扩展，不再更新；q 的原代价 16（经 p→q）可被更小路径 h→q 更新为 10。
  • 结束了吗？ —— 并没有，只有边界为空才算结束（目标节点被从边界中取出时才返回，即 "Terminate only when goal is removed from Frontier"）。

一致代价搜索（UCS）

代价最优性？

  • UCS 总是从优先队列里取出路径代价最小的节点进行扩展。
  • 条件：边的代价（动作代价 step cost）必须非负。
  • 原因：UCS 总是从优先队列里取出路径代价最小的节点进行扩展。当目标节点第一次被取出时，它的路径代价已经是最小的（否则 UCS 早就会先扩展更便宜的路径）。
  • 结论：在非负代价下，UCS 一定找到最优解（最小总代价的解）。

空间复杂度？

  • UCS 必须把所有边界（frontier）节点（优先队列）存起来，因为随时可能要从中取出最小代价的节点。
  • 所以空间复杂度 ≈ 时间复杂度。
  • UCS 的最大代价是存储整个边界，和 BFS 一样，空间开销非常大。

总结：搜索算法

算法核心特点优势应用
BFS（广度优先）用队列，逐层展开，保证找到最浅解找最少步数的解（所有边代价相同）社交网络最短关系链（如 Facebook/LinkedIn 好友推荐） / 迷宫、棋盘最少步数解
DFS（深度优先）用栈或递归，沿一条路径走到底再回溯，空间省快速找到一个解，不保证最浅解程序分析 / 推理链搜索
DLS（深度受限）在 DFS 基础上设定深度上限避免 DFS 掉进无限深度爬虫设深度限制，防止死循环
IDS（迭代加深）多次限制深度的 DFS，结合 BFS 的代价最优性和 DFS 的省空间在不知道解深度时，既保证找到最浅解，又节省空间路径规划（在空间有限时比 BFS 更好） / 机器人探索未知环境
UCS（一致代价）用优先队列，每次扩展总代价最小的节点找总代价最小的解，适合边代价不等地图/GPS 路径规划（高德/Google Maps，最短路径） / 机器人运动规划（能量消耗最小路径）
  • 定义：状态空间、初始状态、动作（集）、转移模型结果 (s,a)、目标状态、路径代价
  • 搜索类型：
    • 盲目搜索（无信息搜索）——只用深度和路径代价：广度优先搜索、一致代价搜索、深度优先搜索、深度受限搜索、迭代加深搜索、双向搜索
    • 启发式搜索（有信息搜索）——扩展可能计划：树搜索 / 图搜索（避免重复探索）→ 已达、边界
  • 评估函数：完备性、代价最优性、复杂度

1. 选择：BFS 使用的数据结构是？A. 栈　B. 队列（FIFO）　C. 优先队列　D. 哈希表

答案：B。先入队的节点先被取出扩展。

2. 选择：DFS 使用的数据结构是（可多选）？A. 栈　B. 递归　C. 队列　D. 优先队列

答案：A、B。栈（LIFO），或用递归实现。

3. 判断：在单位代价（每步代价相同）下，BFS 是完备且代价最优的。

答案：对。BFS 逐层扩展，找到最浅解即最短步数解。

4. 判断：在无限深的状态空间中，DFS 可能永远找不到解。

答案：对。DFS 会沿一条路径无限深入，可能错过浅层解，不保证完备。

5. 判断：DLS 只能找到深度 ≤ ℓ 的解；真正的解在更深处时 DLS 会失败。
6. 判断：解存在且深度已知上限时，IDS 一定找到最浅解。
7. 选择：IDS 的时间/空间复杂度是？A. O(bd)/O(bd)　B. O(bd)/O(bd)　C. O(bd+1)/O(bd)　D. O(bd)/O(bd)
8. 选择＋判断：UCS 始终取出哪种节点？A. 最先入队　B. 累计路径代价最小　C. 深度最浅　D. 随机；动作代价都相同时，UCS 等价于 BFS。
9. 判断：UCS 在边代价为负时也保证最优。

答案：错。UCS 代价最优性要求动作代价非负。

10. 判断：UCS 中仅"找到目标"不算结束，必须等目标节点从边界（优先队列）中取出才返回。
11. 选择（水罐）：用 BFS 求解水罐问题，初始 (0,0)、目标 (*,2)，动作同 P04。最短解需要多少步？A. 5 步　B. 6 步　C. 7 步　D. 8 步

答案（6 步）：(0,0) → 满-3 → (3,0) → 转3→4 → (0,3) → 满-3 → (3,3) → 转3→4 → (2,4) → 空-4 → (2,0) → 转3→4 → (0,2)。每步代价相同，BFS 保证为最短（步数最少）。

说明：另一条常见解为 (0,0)→满-4→(0,4)→转4→3→(3,1)→空-3→(0,1)→转4→3→(1,0)→满-4→(1,4)→转4→3→(3,2)→空-3→(0,2)，共 7 步，合法但非最短。

12. 选择＋判断：设 b=4、d=10，BFS 与 IDS 谁生成的状态更多？A. BFS　B. IDS　C. 相同　D. 无法比较；IDS 的状态数 = 1,864,131。

答案：IDS = 1,864,131；BFS = 5,592,401。BFS 更多（多出第 d+1 层子节点 4(410−1)）。
